# Implementation clarifications and intentional corrections

These clarifications apply to V04. The six V03 input documents are preserved in `specifications/` for comparison. Native schema 14 and all operational domain modules remain unchanged.

1. **Feature dependency does not assert activation.** `conditionsVariationPoint` replaces the proposed `activatesVariationPoint`. A feature inside `NOT`, an OR expression, or a value rule cannot independently be said to activate a VP. Expressions, value conditions, enabled state and rule IDs remain attributes. Actual application comes from frozen `appliedVariations`.
2. **Identity uses encoded tuples.** Owner/child IDs are JSON tuples before URI encoding. This prevents `a/b` + `c` from colliding with `a` + `b/c`. A derivation context includes both Configuration and Derivation IDs. Semantic IDs are Project-scoped; aggregate consumers must also use the exported Project ID.
3. **Role and provenance are independent.** A typed reference can be canonical, supporting, constraint or evidence. Stored relationship directions are unchanged. Inverse projections retain the actual field owner in provenance.
4. **Navigability is not a fabricated forward workflow.** `traceCanonical` uses canonical edges only. Mission-to-baseline navigation may require inverse navigation and supporting/evidence edges, as existing `scopes`, membership and evidence fields have different directions. The acceptance test checks navigability with these roles while testing stored directions independently. No edges are invented to make the drawing a single forward chain.
5. **Live evidence is an index.** Live views include Run and Realization identities and context selectors, without importing historical element/result topology into current nodes. Matching explicit derivation identities are reused. Background run derivations remain tied to their captured Run. Open the corresponding historical context for frozen topology.
6. **Frozen identity references are explicit.** `referenceOnly` means an identifier was captured but the full definition was not. It does not claim that today's record was present at run time. Actual unresolved references produce diagnostics and placeholders, with no dangling edges. A Decision without a snapshot has a marked current display fallback and no reconstructed historical selection.
7. **Derivation KPI values are retained without invented definitions.** `calculatedKpiValues` supports frozen KPI reference nodes with captured values and `definitionCaptured=false`. Definitions, units and formula topology are not taken from live KPIs. Simulation values use `inputSnapshot.parameterValues` when available, ahead of the embedded parameter's earlier value.
8. **Historical Decision truth comes from its snapshot.** Candidate alternatives, criteria, risks and evidence values use the captured snapshot. Current Decision status is not presented as a frozen status. Live Decisions with snapshots direct users to the Decision context instead of resolving their selection against modified studies. Labels are resolved only within recorded support, with ID matches taking precedence and ambiguity reported.
9. **Legacy Feature grouping is handled conservatively.** `parentGroupId` references an actual FeatureGroup. Legacy `groupId` is projected as membership only if that FeatureGroup exists; otherwise it remains the XOR/OR grouping attribute used by the existing engine.
10. **Additional authoritative mappings are included.** Parameter calculation bindings, `Study.exploredFeatureIds` and `Study.selectedKpiIds` are projected explicitly as `providesInputToParameter`, `exploresFeature` and `evaluatesKpi`. VP and Realization relationship targets remain metadata references to graph edge IDs.
11. **The actual Trade Study route is covered.** App mounts `SimplifiedTradeStudyWorkspace`; its semantic preview is additive. The older `TradeStudyOntologyView` also retains its legacy implementation and gets a parallel toggle. The old implementation is not deleted or redirected.
12. **The Modeler inspector lives inside Element details.** The existing modal backdrop prevents interaction with controls outside that panel. The inspector therefore opens inside the current editor, displays saved-model context, and preserves unsaved drafts and all existing editing actions.
13. **Scope layout remains available unchanged.** The original static layout, routing, scope controls and register are retained. New instance/schema views reuse the visual language of workflow bands, orthogonal links, distinct ports, expandable labels, pan/zoom, search and inspection. Their deterministic layout supports heterogeneous instances and does not write positions to Project.
14. **Performance is a separate gate.** The specified 75/250 ms projection budgets run in a dedicated single-worker command. They are not relaxed. This avoids measuring contention from the large existing browser-emulation suite as projector latency.

`completeness` describes projection/reference diagnostics, not engineering approval or global digital-thread completeness. Domain validity, requirement verification, simulation currency and baseline approval remain separate existing concepts. The semantic export is not a native Project backup or an import format. Function sequences, units, custom attributes, scenarios and robustness machinery keep their existing operational representation; the graph does not become a replacement for native persistence.
